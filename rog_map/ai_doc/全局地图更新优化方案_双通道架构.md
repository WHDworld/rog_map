# 全局地图更新优化方案：双通道架构

## 问题定义

### 现象
当前使用 LiDAR 进行探索时，虽然 LiDAR 感知范围可达 **30m**，但实际有效感知范围被限制在 **局部地图范围（10m）**。超出局部地图范围的点云数据在全局地图中没有被更新。

### 根因分析
当前数据流路径：
```
LiDAR PointCloud  →  LocalMap::insertPointCloud()  →  syncLocalToGlobal()  →  GlobalMap
                          ↓
              isInLocalMap(pos) 过滤  ← ❌ 超出 10m 的点被丢弃
```

关键代码位置 (`local_map.cpp:320`)：
```cpp
// 当前逻辑：超出 LocalMap 范围的点直接跳过
if (isInLocalMap(end_pos)) {
    int hash_id = posToHash(end_pos);
    candidate_occupied_voxels.insert(hash_id);
    valid_endpoints.emplace_back(end_pos, hash_id);
}
```

### 影响
1. **探索效率下降**：无人机必须飞到远距离区域附近才能感知到那里的障碍物和前沿。
2. **全局规划质量降低**：HistoryGraph 路径代价计算依赖 GlobalMap 的障碍物信息，远距离障碍物缺失会导致路径规划不准确。
3. **资源浪费**：LiDAR 已经获取了有效数据，却被人为丢弃。

## 优化方案：双通道更新架构

### 设计思路

保留 LocalMap 的核心功能（高频滑动窗口、精细 Raycast 概率更新），同时新增一条直连 GlobalMap 的通道，专门处理超出 LocalMap 范围但在 LiDAR 有效感知范围内的点云。

**数据流（优化后）：**
```
LiDAR PointCloud 
      ↓
  ┌─────────────────────────────────────────────────────┐
  │  MapManager::lidarCallback()                        │
  │                                                     │
  │  ┌─── 通道 A：近程（LocalMap 范围内）────────────┐  │
  │  │  LocalMap::insertPointCloud()                 │  │
  │  │    → Raycast + 概率更新                       │  │
  │  │    → syncLocalToGlobal() → GlobalMap          │  │
  │  └───────────────────────────────────────────────┘  │
  │                                                     │
  │  ┌─── 通道 B：远程（超出 LocalMap 但在 LiDAR 范围）┐│
  │  │  GlobalMap::insertFarRangePoints()            │  │
  │  │    → 直接标记 OCCUPIED                         │  │
  │  │    → 不做 Raycast（计算量过大）               │  │
  │  │    → 触发前沿增量更新                          │  │
  │  └───────────────────────────────────────────────┘  │
  └─────────────────────────────────────────────────────┘
```

### 方案特点

| 特性 | 通道 A（近程） | 通道 B（远程） |
|------|----------------|----------------|
| 范围 | 0 ~ 10m (LocalMap) | 10m ~ 30m (LiDAR Max) |
| Raycast | ✅ 完整 Raycast | ❌ 不做 Raycast |
| 概率更新 | ✅ Log-Odds 累积 | ❌ 直接标记 OCCUPIED |
| Free 空间更新 | ✅ 沿射线清空 | ❌ 不清空 |
| 膨胀地图同步 | ✅ | ✅ |
| 前沿提取 | ✅ | ✅ |
| 计算开销 | 高 | 低 |

### 设计权衡

**为什么远程通道不做 Raycast？**
1. **计算量爆炸**：30m 范围的 Raycast 步长 0.1m 意味着单条射线需要 300 步，数千点云会导致数十万次体素访问。
2. **概率更新冲突**：远程点云稀疏，Raycast 会错误地将大片区域标记为 FREE，与实际情况不符。
3. **工程实践**：多数探索系统（如 FUEL、FALCON）对远程感知也只做 OCCUPIED 标记，不做 Raycast。

**远程 Free 空间如何获知？**
- 依赖 LocalMap 的滑动窗口机制：当无人机移动到远程区域后，该区域将进入 LocalMap 范围，此时会进行完整的 Raycast 更新。
- 即：远程先感知障碍物，近程再细化 Free 空间。

#### 文件: [global_map.cpp](file:///home/whd/experiment/STAR-Searcher/src/ROG-Map/rog_map/src/star_mvf/map/global_map.cpp)

实现该函数：
```cpp
void GlobalMap::insertFarRangePoints(const std::vector<Position>& points) {
    if (points.empty()) return;
    
    std::lock_guard<std::mutex> lock(map_mutex_);
    
    for (const auto& pos : points) {
        // 范围检查
        if (!isInGlobalMapRange(pos)) continue;
        
        // 高度过滤（可选，避免地面/天花板噪点）
        if (pos.z() < config_.frontier_height_min - 0.5f || 
            pos.z() > config_.frontier_height_max + 1.0f) {
            continue;
        }
        
        VoxelIndex idx;
        posToIndex(pos, idx);
        
        // 直接标记为 OCCUPIED
        auto it = voxels_.find(idx);
        if (it == voxels_.end()) {
            // 新体素
            VoxelState state;
            state.occupied = true;
            state.free = false;
            state.frontier = false;
            state.visited = false;
            voxels_[idx] = state;
            
            // 更新膨胀地图
            updateInflation(idx, true);
            
            // 标记所属子网格为 dirty（触发前沿增量提取）
            SubGridIndex sg_idx;
            voxelToSubGrid(idx, sg_idx);
            int sg_linear = subGridToLinearIndex(sg_idx);
            if (sg_linear >= 0 && sg_linear < static_cast<int>(sub_grids_.size())) {
                dirty_subgrids_.insert(sg_linear);
            }
        } else {
            // 已有体素，确保为 OCCUPIED
            if (!it->second.occupied) {
                it->second.occupied = true;
                it->second.free = false;
                it->second.frontier = false;
                updateInflation(idx, true);
                
                SubGridIndex sg_idx;
                voxelToSubGrid(idx, sg_idx);
                int sg_linear = subGridToLinearIndex(sg_idx);
                if (sg_linear >= 0 && sg_linear < static_cast<int>(sub_grids_.size())) {
                    dirty_subgrids_.insert(sg_linear);
                }
            }
        }
    }
}
```

#### 文件: [local_map.cpp](file:///home/whd/experiment/STAR-Searcher/src/ROG-Map/rog_map/src/star_mvf/map/local_map.cpp)

修改 `insertPointCloud()` 函数，在距离过滤后、抛弃远程点之前，将其缓存：

```cpp
void LocalMap::insertPointCloud(const sensor_msgs::PointCloud2& cloud, const Position& sensor_pos) {
    pcl::PointCloud<pcl::PointXYZ> pcl_cloud;
    pcl::fromROSMsg(cloud, pcl_cloud);
    
    std::lock_guard<std::mutex> lock(map_mutex_);
    
    // [新增] 清空远程点缓存
    far_range_points_.clear();
    far_range_points_.reserve(pcl_cloud.size() / 10);  // 预分配
    
    std::vector<std::pair<Position, int>> valid_endpoints;
    std::unordered_set<int> candidate_occupied_voxels;
    valid_endpoints.reserve(pcl_cloud.size() / std::max(1, config_.lidar_downsample_filter));
    
    int point_counter = 0;
    
    for (const auto& pt : pcl_cloud) {
        if (config_.lidar_downsample_filter > 1) {
            if ((point_counter++ % config_.lidar_downsample_filter) != 0) {
                continue;
            }
        }
        
        Position end_pos(pt.x, pt.y, pt.z);
        float dist = (end_pos - sensor_pos).norm();
        
        // 距离过滤
        if (dist < config_.lidar_min_range || dist > config_.lidar_max_range) {
            continue;
        }
        
        // ========== [修改] 分流处理 ==========
        if (isInLocalMap(end_pos)) {
            // 通道 A：近程点 → LocalMap 正常处理
            int hash_id = posToHash(end_pos);
            candidate_occupied_voxels.insert(hash_id);
            valid_endpoints.emplace_back(end_pos, hash_id);
        } else {
            // 通道 B：远程点 → 缓存待 GlobalMap 直接处理
            far_range_points_.push_back(end_pos);
        }
    }
    
    // ... 后续 Raycast 和概率更新逻辑不变 ...
}

void LocalMap::getFarRangePoints(std::vector<Position>& out_points) {
    std::lock_guard<std::mutex> lock(map_mutex_);
    out_points = std::move(far_range_points_);
    far_range_points_.clear();
}
```

### 3. [MODIFY] MapManager 调用新接口

#### 文件: [map_manager.cpp](file:///home/whd/experiment/STAR-Searcher/src/ROG-Map/rog_map/src/star_mvf/map/map_manager.cpp)

修改 `lidarCallback()` 和 `syncLocalToGlobal()`：

```cpp
void MapManager::lidarCallback(const sensor_msgs::PointCloud2ConstPtr& msg) {
    // ... 前置检查不变 ...
    
    // Step 1: 更新局部地图（同时收集远程点）
    auto t1 = ros::Time::now();
    local_map_->insertPointCloud(*msg, sensor_pos);
    auto t2 = ros::Time::now();
    
    // Step 2: 相机可视域（不变）
    // ...
    
    // Step 3: 同步到全局地图（包含远程点处理）
    syncLocalToGlobal();
    auto t3 = ros::Time::now();
    
    // ... 后续不变 ...
}

void MapManager::syncLocalToGlobal() {
    // === A. 近程更新（原有逻辑） ===
    std::vector<VoxelIndex> occupied, free_voxels;
    local_map_->getUpdatedVoxels(occupied, free_voxels);

    std::vector<VoxelIndex> observed_voxels;
    if (has_camera_pose_) {
        local_map_->getObservedVoxels(observed_voxels);
    }
    
    if (!occupied.empty() || !free_voxels.empty()) {
        global_map_->updateOccupiedVoxels(occupied, free_voxels);
        
        if (!observed_voxels.empty()) {
            for (const auto& idx : observed_voxels) {
                global_map_->updateVoxelStateFromCamera(idx, true);
            }
        }
    }
    
    // === B. 远程更新（新增） ===
    std::vector<Position> far_range_points;
    local_map_->getFarRangePoints(far_range_points);
    
    if (!far_range_points.empty()) {
        global_map_->insertFarRangePoints(far_range_points);
        ROS_DEBUG_THROTTLE(1.0, "[MapManager] Inserted %zu far-range points to GlobalMap", 
                           far_range_points.size());
    }
    
    // 清除缓存
    local_map_->clearUpdateCache();
    local_map_->clearObservedCache();
}
```

## 配置参数

无需新增配置参数，复用现有：
- `lidar_max_range` (30m)：决定远程通道的最大感知距离
- `local_map/half_size` (10m)：决定近/远程分界

如需微调远程高度过滤，可在 `global_map.yaml` 或代码中调整：
```yaml
# global_map 相关
frontier_height_min: 0.5  # 远程点高度下限
frontier_height_max: 2.5  # 远程点高度上限
```

## 附：其它优化思路（备选）

### 方案 B：扩展 LocalMap 虚拟边界
创建一个低精度的"虚拟 LocalMap"（分辨率 0.5m，范围 30m），专门用于远程 Raycast。
- **优点**：可以正确更新 Free 空间
- **缺点**：内存和计算开销大，实现复杂

### 方案 C：分层地图架构
引入 OctoMap 风格的多分辨率地图，近程高分辨率、远程低分辨率。
- **优点**：理论最优
- **缺点**：架构改动大，需要重构 GlobalMap

**当前推荐方案 A（双通道架构）**，改动最小、风险可控，能解决核心问题。
